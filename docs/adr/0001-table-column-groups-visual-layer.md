# Table 列分组用自绘分组条，而非 RAC 嵌套列

_2026-11-03_

react-aria-components 1.21.1 的 `Column` 是叶子节点（`createLeafComponent`），无法声明嵌套列，因此列分组由库自绘一条 `aria-hidden` 的分组条，位置与宽度直接取 `Table.ManagedColumns` 的列几何；RAC 照常只管理叶子列。代价是读屏器读不到 colspan 结构，以视觉隐藏的分组名拼入叶子列可访问名称作补救。第一版只支持原生 table 模式（分组条放在滚动容器内，靠 CSS sticky 跟随滚动与固定列）；虚拟化模式不支持。上游支持嵌套列后应切回原生语义。

分组条由 `Table.Content` 统一挂载，与原生表格成为同级节点；滚动和列宽调整容器不再承担分组条的渲染职责。这样无论容器如何组合，每张表格都只有一条分组条；分组条用负的下外边距叠在表头上层：分组叶子列的表头单元格（`data-grouped`）留出上层高度，未分组列贯穿两层，其上方是透明且不吸附的空白段。为让横向滚动的分组段从固定的未分组列下方滑过，有分组条时 `<thead>` 不再 sticky（sticky 必然形成层叠上下文），改由表头单元格各自吸附并与分组条交错分层：普通 30 < 固定分组列 40 < 分组条 45 < 固定未分组列 50。分组 `id` 必须唯一，避免将不同标题的相邻分组误合并。

## 考虑过的方案

- 在每个叶子列上加 `group` 字段：分组数据散落各列，否决。
- 分组被固定区切开时要求同区并报警：按「分组 + 固定区」切连续分组段的代码量相同且行为更完整，否决。
