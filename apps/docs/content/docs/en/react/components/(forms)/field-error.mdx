## Usage

```tsx
import { FieldError } from '@sy-inc/react';
```

<ComponentPreview
  name="field-error-basic"
/>

FieldError displays the error message for a form control and renders nothing when there is no error. Inside a React Aria field (`TextField`, `Select`, `RadioGroup`, …) the field's invalid state decides; everywhere else, the message you pass decides. See [Outside React Aria Fields](#outside-react-aria-fields).

## Examples

### Basic Validation

```tsx
export function Basic() {
  const [value, setValue] = useState("");
  const isInvalid = value.length > 0 && value.length < 3;

  return (
    <TextField className="w-64" isInvalid={isInvalid}>
      <Label htmlFor="username">Username</Label>
      <Input
        id="username"
        placeholder="Enter username"
        value={value}
        onChange={(e) => setValue(e.target.value)}
      />
      <FieldError>Username must be at least 3 characters</FieldError>
    </TextField>
  );
}
```

### With Dynamic Messages

```tsx
<TextField isInvalid={errors.length > 0}>
  <Label>Password</Label>
  <Input type="password" />
  <FieldError>
    {(validation) => validation.validationErrors.join(', ')}
  </FieldError>
</TextField>
```

### Custom Validation Logic

```tsx
function EmailField() {
  const [email, setEmail] = useState('');
  const isInvalid = email.length > 0 && !email.includes('@');

  return (
    <TextField isInvalid={isInvalid}>
      <Label>Email</Label>
      <Input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
      <FieldError>Email must include @ symbol</FieldError>
    </TextField>
  );
}
```

### Multiple Error Messages

```tsx
<TextField isInvalid={hasErrors}>
  <Label>Username</Label>
  <Input />
  <FieldError>
    {errors.map((error, i) => (
      <div key={i}>{error}</div>
    ))}
  </FieldError>
</TextField>
```

### Outside React Aria Fields

The same `FieldError` works next to any control. Where there is no field state to read, the content is the error: pass a message and it shows; pass nothing (`undefined`, `null`, `false`, `""`, `[]`) and it renders nothing.

```tsx
<InputOTP aria-describedby={error ? "code-error" : undefined} isInvalid={!!error} maxLength={6}>
  ...
</InputOTP>
<FieldError id="code-error">{error}</FieldError>
```

| Control | Mark invalid | Link the message |
|---------|--------------|------------------|
| React Aria fields (`TextField`, `Select`, `CheckboxGroup`, `RadioGroup`, `Switch`, …) | `isInvalid` on the field | Automatic — place `FieldError` inside the field |
| `Calendar`, `RangeCalendar`, `TagGroup` | `isInvalid` on `Calendar` / `RangeCalendar` | Automatic — place `FieldError` inside the component |
| `InputOTP`, `InputPhone`, `ListBox`, `CellColorPicker` | `isInvalid` | `aria-describedby` on the control (`InputPhone.Input`, `CellColorPicker.Trigger`) |
| `DropZone` | — (the Area shows its own validation state) | `aria-describedby` on `DropZone.Area`; it forwards to the upload triggers |

`<FieldError>{error}</FieldError>` reads the same everywhere — inside a field, pair it with `isInvalid={!!error}` on the field.

## API Reference

### FieldError

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `className` | `string` | - | Additional CSS classes |
| `children` | `ReactNode \| ((validation: ValidationResult) => ReactNode)` | - | Error message content or render function. Outside a React Aria field, empty content renders nothing |
| `id` | `string` | - | Target for the control's `aria-describedby` outside a React Aria field |

## Accessibility

The FieldError component ensures accessibility by:

- Inside a React Aria field, linking the message to the input through `aria-describedby` and rendering it only while the field is invalid
- Inside `Calendar`, `RangeCalendar` and `TagGroup`, linking the message to the grid automatically
- Outside a field, rendering only while it has content; link it with `id` + `aria-describedby` on the control
- Not rendering hidden messages, so screen readers never read a stale error
